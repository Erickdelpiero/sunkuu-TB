## 2. Contenido del módulo

**API pública (`SunkuuRegistro`)**

| Miembro | Uso |
|---|---|
| `VERSION` | `"B-02 2026-10-21"`. Permite ver en consola qué versión cargó el widget |
| `MSG_VACIO` | `"No hay instalaciones asignadas"` |
| `CATALOGO` | Congelado (`Object.freeze` profundo): ningún widget lo puede modificar |
| `loadInstallations(ctx, cb)` | Q1 → `cb({ instalaciones, ok, estado, mensaje, descartadas })`, una sola vez |
| `porDashboard(lista, dashId)` | Instalación de un dashboard (Exportación `?from=`, NAV) |
| `dispositivoFlota(inst)` | `dispositivos[catalogo[tipo].flota.rol]` (3EM `principal`, Piscina `cal`) |
| `exportacion(inst)` | `{ devices:[{rol,id,nombre}], varGroups:{grupo:[{k,l,deviceId,di}]} }` en el orden de hoy. Omite las variables de un rol opcional sin dispositivo |
| `opcionesNav(lista, dashId)` | §2.3: mismo `owner`, sin la actual; las de prueba solo si la actual es de prueba; dashboard fuera del registro → `[]` |

**Instalación normalizada:** `{ id, name, etiqueta, ubicacion, tipo, dashboardId, dispositivos:{rol:uuid}, orden (número o null), esPrueba, mostrarParametros, activa:true, owner }`. `etiqueta` toma `label` y luego `name` si falta.

**Catálogo frente a HEAD.** `roles.*.nombre` de Piscina reproduce los nombres de dispositivo que Exportación usa hoy en los mensajes de progreso. Los de 3EM ("Medidor (Pro 3EM)") son nuevos: hoy se usa el `name` del dispositivo. Con P-11, el CSV pasa a usar la etiqueta de la instalación. `proem` lleva `roles` y `nombre`; `template_widget`, `flota` y `export` quedan vacíos hasta la Opción A.

**Decisiones de detalle (no estaban fijadas en el diseño):**
- La firma es `loadInstallations(ctx, cb)`, no `(scope, cb)`: se necesita `ctx.http`.
- Un rol opcional con UUID inválido se ignora con aviso (la instalación se muestra). Un rol que no existe en el tipo también se ignora con aviso.
- `activa` con un valor inválido (ni `true` ni `false`) se toma como `true`, con aviso.
- `hasNext` (más de 200) solo avisa. Con la licencia de 100 activos no ocurre.
- El módulo no puede verificar que `owner` sea el customer del usuario: Q1 no trae `ownerId`. El filtrado del cliente lo hace ThingsBoard por permisos [B-00, B-01].
