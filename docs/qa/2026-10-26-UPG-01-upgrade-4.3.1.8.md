## Resumen

- **Ruta:** la guía oficial permite subir de "cualquier parche 4.3.x" a 4.3.1.x directamente. **Desde 4.3.x no se ejecuta el script de upgrade** ("if you are upgrading from version 4.3.x, DO NOT run the upgrade script; proceed directly to starting the service"). En nuestro Compose propio eso se traduce en: cambiar las dos imágenes, parar y arrancar.
- **Imágenes:** `thingsboard/tb-pe-node:4.3.0PE` → `:4.3.1.8PE` y `thingsboard/tb-pe-web-report:4.3.0PE` → `:4.3.1.8PE` (servicios `thingsboard-pe` y `tb-web-report` de `~/gonex/docker/docker-compose.yml`). El resto del stack (Postgres, Mosquitto, n8n…) no se toca.
- **Migración de alarmas:** desde 4.3.1.4 las alarmas pasan a un formato nuevo. Viniendo de 4.3.0 la migración corre **en segundo plano** después del arranque; las alarmas viejas pueden no verse hasta que termine. El log `Applied LTS migration 4.3.1.4` marca el final. Por eso **el rollback vuelve a la base de antes del upgrade**: volver solo a la imagen 4.3.0PE sobre una base migrada no es seguro. Esa base es una copia hecha en la ventana con ThingsBoard parado (§4.3, decisión 5).
- **Angular 20 (desde 4.3.1):** "custom UI code (widgets or custom CSS) that relies on internal component structure or CSS variable names may break". Revisado en `ce213c8`: los widgets propios no usan clases internas de ThingsBoard ni de Angular Material (solo `tb-num`, propia de Flota), pero **el CSS avanzado del login** (`config/white-labeling/login-advanced.css`) usa `.mat-mdc-*`, `tb-login-content`, `tb-password-card` y 13 variables `--mdc-*`. Es el punto más probable de rotura (solo estético). Además, 7 widgets llaman a la API con `localStorage.jwt_token` (Portal de Flota, Template 3EM y Template Piscina de producción, y sus copias DEV `f2b42860`, `3b5205e0`, `afc86b80` y `aff83c70`): si 4.3.1 cambia dónde guarda el token, dejan de cargar datos. El checklist (§6) cubre ambos.
- **Telemetría durante la caída:** las 5 integraciones MQTT usan `cleanSession: true` y QoS 0 (salvo 2 filtros del Pro EM50 con QoS 1, que con `cleanSession` tampoco se guardan). Lo que publiquen los Shelly mientras ThingsBoard esté parado **se pierde**. La energía diaria y mensual se recupera sola (FIX-01 usa diferencia de contador); la potencia instantánea y las curvas tendrán un hueco del tamaño de la caída.
- **Sin ensayo en otra máquina** (Erick, 2026-10-26): va directo a producción con rollback. La restauración del backup sí se prueba antes, en el VPS, en una base aparte (§3.4), si el disco alcanza (§0, 0.3: alcanza).
